## 2. Target architecture (status DRAFT)

- Layout: a desktop shell spawns a sidecar backend; the handshake passes
  a per-launch UI session token then a per-launch nonce; the backend boots
  an app factory from settings; app data lives in the app data folder; the
  shell opens the desktop window on the sidecar loopback port; the served UI
  returns the token on every USER write call; browser storage is keyed by
  the loopback origin; one process serves API plus UI.
- Composition root resolves settings with tracing off, runs additive-only
  migrations plus seed and dedupe, builds the manager graph, tool registry,
  guarded dispatcher, handlers, and model factory, mounts sibling routers,
  one open about endpoint, and the SPA fallback last with CSP headers.
  Lifespan: resume orphaned runs, start the scheduler, watcher integrity
  check plus tick registration.
- Route protection maps each path to an action class; chat calls need an
  actor header; the token check runs first in every USER write handler;
  reads need no token.
- SDK boundary: code-first on one orchestration interface plus one adapter,
  SDK-first rules; a replacement runtime needs evidence, a decision record,
  and an independent audit.
- Telemetry: core accounting ALWAYS_ON; the event envelope carries the
  project link and the metric entries own value, state, and source; wall
  time is the interval union; cost is UNAVAILABLE without a price snapshot;
  analytics and report exports derive only from stored telemetry.
- Scheduler: precheck, routing decision, reserve, attempt gate; persistent
  leases plus reservations; restart reconciliation; no forced local runs.
- Authorization ladder R0 read-only auto, R1 reversible local writes, R2
  director-approved external writes, R3 user-approved destructive writes;
  agents hold secret refs, never raw values; policy objects are immutable,
  versioned, and hash-addressed; the finalizer binds the exact audit record
  and writes the finalization record; cancellation keeps history.
- Tracing decision: default DISABLED for every project and run; enabling
  needs an explicit project-plus-run policy; external export additionally
  needs authorization, a configured key, and redaction; secrets-bearing
  traces stay local and redacted; raw values are never exported.
- Budget: atomic compare-and-reserve before billable calls, deterministic
  settlement, derived remaining, per-provider caps; the provider
  usage-reporting capability is probed and recorded.
- Module ownership map: longest-prefix match, clash list EMPTY; ownership
  by role - K02 hierarchy and orchestration; K03 assurance, catalog, and
  test stage; K04 providers, routing, model knowledge, and budget; K05
  local AI; K06 tool belt, permissions, and services; K07 shell, UX, cards,
  and languages; K08 watcher, automations, and context; K09 knowledge
  bases; K10 installer, proofs, and acceptance; K11 follow-up plan-only;
  K12 presentation and demo; K13 run core: contracts, state machines,
  storage, telemetry, SDK adapter, and the frozen manifest.
- Canonical glossary: Project, Task, TaskContract, ExecutionRun,
  ExecutionAttempt, TaskPackage, AgentTask, TelemetryEvent, MetricRecord,
  RoutingDecision, policy objects, canonical audit result PASS | REWORK |
  BLOCKED | ESCALATE | FAIL, completion dispositions, FinalizationRecord,
