# K09 — development knowledge bases

## 1. What was built

Lane A — KB registry, retrieval path, HTTP routes.

Product files:

- `src/agent_si/kb/__init__.py`
- `src/agent_si/kb/iface_kb.py` (frozen contract stub)
- `src/agent_si/kb/models.py`
- `src/agent_si/kb/registry.py`
- `src/agent_si/kb/retriever.py`
- `src/agent_si/kb/guard.py`
- `src/agent_si/backend/kb_routes.py`
- `tests/test_k09a_contract.py`
- `tests/test_k09a_retrieval.py`

Behavior, one line each:

- Manifest-index-first reads: every section read goes through a manifest lookup first.
- Per-call section-touch log with token cost: each `retrieve()` call returns the sections touched plus the token cost.
- Whole-KB refusal: whole-KB reads are refused instead of served.
- DATA_ONLY guard: retrieved chunks stay data only and never redefine governance, permissions, contracts, instructions, or workspaces.
- Flat-md adapter: a documented adapter loads foreign-shaped (flat markdown) KBs through the universal connector.

Lane B — telemetry, savings, validator, docs.

Product files:

- `src/agent_si/kb/telemetry.py`
- `src/agent_si/kb/savings.py`
- `tools/kb_validator/iface.py`
- `tools/kb_validator/validate_kb.py`
- `docs/kb_format/FORMAT.md`
- `docs/kb_format/BUILDER_GUIDE.md`
- `docs/kb_format/KEEPER_GUIDE.md`
- `docs/kb_format/templates/manifest.json`
- `docs/kb_format/templates/section.md`
- `tests/test_k09b_contract.py`
- `tests/test_k09b_telemetry.py`
- `tests/test_k09b_validator.py`

Behavior, one line each:

- Per-role/agent hit-miss-web-fallback counters with tokens and cost: every hit, miss, and web fallback is counted per role and agent with its tokens and retrieval cost.
- Savings-from-stored-records-only: the savings report is computed only from stored telemetry records, never from hand-computed figures.
- Validator CLI codes: the validator CLI accepts a well-formed KB and rejects malformed ones with exact error codes.
