## 1. What was built

- Lane A1 (registry + health + adapters): provider registry API (register /
  get / list evidenced-only / record health / remove) with per-instance
  health latest-wins and ONLINE kept distinct from READY; generic Chat
  Completions compat adapter; injected-callable adapter; one leg per
  provider plus a mock leg that marks every record and retires on a user
  key; per-adapter usage probes recorded separately with partial results
  reported as UNAVAILABLE. Facades landed for the frozen D10/D11/D12 rows
  (module-level functions over the registry API, fail-closed usage probe,
  verbatim-id model resolution). The DELTA-1 leftover-key listing landed as
  an additive route (pending HD decision, see section 7).
- Lane A2 (router + fallback + roles / pools + pools routes): canonical
  ordered selection (hard capability first, price / latency last, quality
  and risk gating before price); per-role PINNED / pool / AUTO resolution
  with BLOCKED plus reason on fresh installs; pool strategies (auto,
  decide, fallback order, split parallel) picked through opaque keys with
  raw ids kept on the backend; fallback records carry a reason drawn from
  a frozen accepted set; persisted decisions replay byte-equal after health
  changes. Pools routes serve the frozen 11 routes with legacy rows kept
  and USER writes guarded (401 plus frozen wording without a session
  token).
- Interface stub plus declaration file: routing interface stub (8 owned
  surface prefixes) pinned by the contract test, plus the D15 declaration
  file the d15 conformance test checks against (REQUIRED plus ACCEPTED
  props, optionality enforced). Fifteen drifts D1-D15 recorded in the HD
  request files (frozen, read-only).
- Lane B1 (model KB): catalog format p17ub-kb/1 with every field carrying
  its value plus retrieved-at dating; UNKNOWN for anything unproven, never
  guessed; exact-id bridge with dated snapshots and local tags; AUTO reads
  connected providers only; allowlisted fetch parsed as data only;
  proposals apply only on explicit user confirm with version bump and
  changelog entry; one-click offer picks the strongest text / tools /
  coding model, never image / audio / embedding, never alphabetical,
  connected-only, with no invented numbers. Six facades expose the frozen
  D8/D14 rows with legacy functions intact.
- Lane B2 (budget + telemetry): atomic compare-and-reserve under one lock;
  settlement dedupe by key; PENDING-RECONCILIATION for settlements without
  usage evidence; restart reconcile that settles with evidence, releases
  expired unused holds, and never double-settles; derived remaining (never
  stored); soft warnings vs hard blocks with override refs; per-provider
  caps; pinned breach wording; local zero-cost bypass; validated metric
  records; cost calculator that raises when the price snapshot is absent
  (never zero) with 6dp totals; envelope dedupe; routing reasons carrying
  estimate, currency, remaining, hard limit, and route. Budget route added
  to the route table from the owned package.
- Lane B3 (ProvidersPage): 14 owned files under
  frontend/src/settings/ProvidersPage, adding RolePoolPicker,
  ChatModelSelector, and LeftoverKeyFinder plus an embedded setup wizard;
  key-only connect (single password input, stored refs carry ids only);
  stable sorted lists; confirm-behind-token finder with linked-guard;
  pool options computed from enabled chat choices, passed with change
  handling to every picker, page-level fetch-mock tests.
- Integration skeleton: fake-only mini-drive harness (no product imports,
  stdlib plus pytest only) covering single-provider hierarchy pass,
  multi-provider auditor leg, spend-cap blocks, first-error stops, the
  skipped live leg, and run-record fields.
